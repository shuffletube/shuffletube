# ShuffleTube

ShuffleTube is an experimental YouTube discovery tool built around a simple idea:

> **Give me a strange video I probably would not have found myself.**

Instead of trying to predict what a user will enjoy, ShuffleTube explores a different part of YouTube: obscure uploads that can be reached through ordinary, automatically generated file names and naming conventions.

The project combines this discovery system with a randomized 3D room, turning the search process into a small interactive experience rather than a normal search form.

---

## How it works

At the center of ShuffleTube is the main button.

Depending on the user's Advanced Mode settings, pressing it can:

- generate a random search code;
- search YouTube through the YouTube Data API;
- choose and open one result automatically;
- or generate a normal YouTube search string and open the YouTube results page.

The goal is not to find the "best" video.

The goal is to find something **unexpected**.

---

# The search-code technology

The most important part of ShuffleTube is the search map.

Many videos are uploaded with names automatically generated by cameras, phones, screen recorders, games, editing software, and other programs.

Examples:

```text
IMG 4827
MVI 0039
DSCF7281
DSCN1456
GOPR1847
PXL 20210314
Screen Recording 2014
Capture 2010
```

These are interesting because they are not typical human-written search terms.

A normal YouTube search might be:

```text
funny cat video
```

ShuffleTube might instead search:

```text
GOPR1847
```

or:

```text
IMG 4827 before:2015
```

The idea is that ordinary-looking machine-generated names can lead to videos that are much less likely to be reached through normal recommendations.

---

# The Map

ShuffleTube does not use one single naming pattern.

It uses a map of families and templates.

A simplified example:

```text
PHONE
  IMG {n4}
  PXL {n4}
  VID {date}

CAMERA
  DSC {n4}
  DSCF{n4}
  DSCN{n4}
  MVI {n4}

ACTION CAM
  GOPR{n4}
  GP01{n4}
  GX01{n4}

SCREEN / EDITOR
  Capture {date}
  Screen Recording {date}
  Untitled Project
```

A **Family** is a group of related naming conventions.

For example:

```text
Family = Camera
```

means the generator only chooses camera-style patterns.

```text
Family = Any
```

allows it to choose from the whole map.

The map is intentionally broad so that one search path does not define the entire discovery system.

---

# Random tokens

Templates can contain special placeholders.

## `{n4}`

A random four-digit number:

```text
MVI {n4}
```

can become:

```text
MVI 7391
```

## `{n3}`

A random three-digit number:

```text
VID {n3}
```

can become:

```text
VID 042
```

## `{n2}`

A random two-digit number:

```text
GP01{n2}
```

can become:

```text
GP0148
```

## `{date}`

A generated date:

```text
VID {date}
```

can become:

```text
VID 2014-07
```

These tokens allow a single template to create many different search paths.

---

# Search operators

Templates can also contain normal search operators.

Examples:

```text
GOPR{n4} before:2008
IMG {n4} before:2015
MVI {n4} before:2012
```

A generated search might therefore become:

```text
GOPR4827 before:2008
```

This lets the generator vary both the machine-generated filename and the time period being searched.

---

# What happens when a search returns nothing?

Empty searches are normal.

For example:

```text
DSCI5589
```

might return no useful videos.

ShuffleTube treats that as part of discovery rather than as an error.

API Discovery can silently generate another search:

```text
DSCI5589
    ↓
0 results

DSCF2741
    ↓
0 results

IMG 4837
    ↓
results found
```

The user does not have to manually repeat the search.

# API Discovery

API Discovery uses the **YouTube Data API v3**.

The general process is:

```text
Generate code
      ↓
YouTube Data API
      ↓
up to 50 results
      ↓
remove previously delivered IDs
      ↓
apply selected preferences
      ↓
choose one result
      ↓
open YouTube
```

When a result is selected, ShuffleTube opens that video directly.

The browser also stores previously delivered YouTube video IDs locally so the discovery system can try to avoid repeating the same video.

The stored data is only a small amount of local browser state. ShuffleTube does not download or store the video itself.

### API key

API Discovery requires a YouTube Data API v3 key.

The key is stored locally in the user's browser and is used directly by the client-side application.

The project does not require a separate backend server for this feature.

---

# Search String Mode

Search String Mode is completely separate from API Discovery.

It does not need a YouTube API key.

The process is:

```text
Generate code
      ↓
Build YouTube search URL
      ↓
Open YouTube search
```

The user then explores the normal search results themselves.

This mode is useful when someone wants the generator but does not want to give the application an API key.

---

# Advanced Mode

Advanced Mode controls the main ShuffleTube button.

## Discovery method

### API Discovery

Uses the YouTube Data API and attempts to open one video automatically.

### Search String

Generates a search phrase and opens the normal YouTube search page.

---

## Family

Family controls the part of the search map used for generation.

Typical choices include:

```text
Any
Phone
Camera
Action cam
Drone / dashcam
Screen recorder
Game capture
Video editor
Formats
Legacy
DVD
Localized
Date-based
AI / modern
```

Choosing `Any` gives the generator the largest search space.

---

## Views

The user can prefer low-view results:

```text
Any
Under 1,000
Under 100
Under 10
0 views only
```

---

## Age

The user can also influence the time range:

```text
Any
Prefer before 2015
Prefer before 2009
Prefer after 2024
```

These preferences affect the generated search expression.

# Curated discoveries

ShuffleTube also contains a local collection of videos in:

```text
videos.txt
```

This collection is intentionally hidden from the main interface.

It exists as a small set of known-good discoveries.

In the completely random API configuration:

```text
Discovery method = API Discovery
Family = Any
```

ShuffleTube can occasionally use one curated discovery instead of performing a fresh API search.

This behavior is intentionally invisible to the user.

When a specific Family is selected, discovery stays focused on that Family.

Search String Mode does not use the curated collection.

# Local use

ShuffleTube is designed to work as a self-contained local project.

The repository contains the HTML, JavaScript, room assets, and local video collection.

For reliable asset loading, it is recommended to run the project through a small local HTTP server rather than opening `index.html` directly.

For example:

```bash
cd path/to/shuffletube
python3 -m http.server
```

Then open:

```text
http://localhost:8000
```

The 3D room and local assets work locally.

### What still needs the internet?

API Discovery needs:

- an internet connection;
- a valid YouTube Data API v3 key.

Search String Mode needs an internet connection when it opens YouTube.

No application backend is required.

---

# Browser memory and repeat avoidance

ShuffleTube keeps a local list of previously delivered video IDs.

This is used to reduce repeats during discovery.

The browser does **not** store:

- YouTube video files;
- complete YouTube pages;
- a growing local copy of search results;
- downloaded thumbnails as a permanent archive.

Only small local browser data is retained.

This means using ShuffleTube for hundreds or thousands of discoveries does not mean thousands of videos are being accumulated in the site's memory.

# The 3D room

The visual part of ShuffleTube is built with **Three.js**.

The room is created from local image assets:

```text
assets/
├── walls/
├── floors/
├── ceilings/
├── posters/
└── objects/
```

Large room surfaces use tiled textures rather than huge background images.

A room can use:

- a randomized wall texture;
- a randomized floor texture;
- a randomized ceiling texture;
- a small number of posters;
- a small number of transparent floating objects;
- randomized room dimensions;
- randomized lighting;
- animated camera movement.

Because the room is assembled from relatively small image assets, the visual environment can change without requiring a large collection of heavy 3D models.

# Why this project exists

YouTube is extremely good at showing people what it thinks they will enjoy.

ShuffleTube explores the opposite direction:

> **What happens when we deliberately search for things the recommendation system has little reason to show us?**

A camera filename is boring.

An automatically generated export name is boring.

An old screen recording is boring.

That is exactly what makes them interesting.

ShuffleTube turns those ordinary machine-generated strings into possible doorways to obscure parts of YouTube.

# Getting a YouTube API key

ShuffleTube includes instructions in its built-in FAQ.

The basic process is:

1. Open [Google Cloud Console](https://console.cloud.google.com/).
2. Create a project.
3. Enable **YouTube Data API v3**.
4. Create an API key.
5. Restrict the key to **YouTube Data API v3**.
6. Paste the key into Advanced Mode.

The exact API quota and Google Cloud billing/limit policies can change, so users should check Google's current documentation for current limits.
